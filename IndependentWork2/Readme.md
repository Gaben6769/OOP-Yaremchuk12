## Опис проєкту
У межах самостійної роботи створено консольний проєкт `IndependentWork2` мовою C#, який моделює систему обліку товарів для інтернет-магазину.

Клас `Product` містить 5 приватних полів (`_id`, `_name`, `_price`, `_category`, `_stockCount`) та публічні read-only властивості для безпечного доступу до них. Для забезпечення гнучкості при створенні об'єктів реалізовано 3 перевантажені конструктори:

1. **Основний конструктор:** приймає всі 5 параметрів та безпосередньо ініціалізує всі поля об'єкта.
2. **Скорочений конструктор:** приймає лише `id`, `name` та `price`, а решту параметрів (`category = "Uncategorized"`, `stockCount = 0`) делегує основному конструктору через синтаксис `: this(...)`.
3. **Конструктор копіювання:** приймає інший об'єкт `Product` і передає його дані в основний конструктор через `: this(...)`, створюючи точний дублікат.

Також перевизначено метод `ToString()` для зручного текстового представлення інформації про товар із форматуванням ціни (`:C`).

## Відповіді на контрольні запитання

1. **Навіщо потрібне перевантаження конструкторів у класі `Product`?**
   Перевантаження конструкторів дає гнучкість при створенні об'єктів залежно від того, скільки інформації про товар відомо на момент створення. Це дозволяє створювати об'єкти як із повним набором характеристик, так і з мінімальними базовими даними (наприклад, при швидкому додаванні позиції на склад) або створювати копії наявних товарів без повторного ручного заповнення кожного поля.

2. **Чому конструктор копіювання зручно реалізовувати через `this(...)`?**
   Делегування виклику через `: this(...)` запобігає дублюванню коду ініціалізації полів. Вся логіка присвоєння значень зосереджена в одному (основному) конструкторі, що спрощує подальшу підтримку та модифікацію класу: якщо структура полів зміниться, оновити ініціалізацію потрібно буде лише в одному місці.

3. **Які переваги дає read-only доступ до властивостей після створення об’єкта?**
   Read-only властивості гарантують **незмінність (immutability)** внутрішнього стану об'єкта після його ініціалізації через конструктор. Це захищає дані товару (ідентифікатор, ціну тощо) від випадкових або некоректних змін з боку зовнішнього коду, забезпечуючи цілісність даних протягом усього життєвого циклу об'єкта.

4. **У яких випадках перевизначення `ToString()` спрощує налагодження та демонстрацію роботи класу?**
   Перевизначення `ToString()` дозволяє отримати зрозуміле, згруповане та відформатоване текстове представлення об'єкта без необхідності вручну звертатися до кожної властивості окремо. Це значно спрощує вивід об'єктів у термінал за допомогою `Console.WriteLine(product)` чи логування, а також прискорює пошук помилок під час налагодження (debugging) у середовищі розробки.
